# 지시 파일 관리

지시 파일은 세션마다 맨 처음 들어가는 입력이다. 낡은 명령 한 줄이 그 뒤 모든 작업을 틀리게 만든다. 이 스킬은 기계 검사를 먼저 통과시키고, 판단이 필요한 항목을 채점해 보고한 뒤, 승인받은 변경만 반영한다.

## 파일과 읽는 도구

| 파일              | 공유 범위           | 읽는 도구                                                                          |
| ----------------- | ------------------- | ---------------------------------------------------------------------------------- |
| `CLAUDE.md`       | 저장소 (커밋)       | Claude Code, omp, Ora                                                              |
| `AGENTS.md`       | 저장소 (커밋)       | omp, Ora. Claude Code는 `CLAUDE.md`가 있으면 읽지 않는다                           |
| `CLAUDE.local.md` | 개인 (`.gitignore`) | Claude Code, Ora. omp는 사용자 설정 `contextFiles.extra`에 이 이름이 있어야 읽는다 |
| `AGENTS.local.md` | 개인 (`.gitignore`) | Ora                                                                                |

Ora는 작업 폴더에서 git 저장소 루트까지 올라가며 네 파일을 모두 읽는다. 홈 디렉터리의 사용자 레벨 파일은 읽지 않는다 (SPEC 5.6절). 그래서 모든 도구에 닿아야 하는 규칙은 저장소 안의 파일에 둔다.

## 두 단계 운용

| 단계 | 파일              | 들어가는 내용                                                                                                  |
| ---- | ----------------- | -------------------------------------------------------------------------------------------------------------- |
| 운용 | `CLAUDE.local.md` | 새 지시, 세션에서 배운 교정, 아직 실행을 확인하지 않은 명령. 항목 끝에 추가한 날짜를 `(2026-10-28)`처럼 적는다 |
| 승격 | `CLAUDE.md`       | 아래 조건을 모두 넘긴 항목. 옮길 때 날짜를 떼고 `CLAUDE.local.md`에서 지운다                                   |

승격 조건은 다섯 가지다.

1. 추가한 날짜로부터 7일 이상 지났고, 그 사이에 항목을 고치지 않았다.
2. 저장소에서 일하는 모든 사람과 에이전트에 해당한다. 개인 경로와 개인 취향은 올리지 않는다.
3. 항목에 적힌 명령과 경로가 지금 저장소에 있다.
4. `SPEC.md`와 다른 지시 파일과 어긋나지 않는다.
5. 사용자가 diff를 보고 승인했다.

## 1. 기계 검사

1. `pnpm check:agents`를 실행한다. agnix가 `@import` 대상, 스킬 frontmatter, 일반론 지시를 검사한다.
2. `pnpm check:claude-md`를 실행한다. 지시 파일에 적힌 `pnpm` 스크립트와 저장소 경로가 실제로 있는지 검사한다.
3. 둘 중 하나라도 실패하면 그 오류부터 고친다. 채점은 두 검사가 통과한 뒤에 한다.

## 2. 찾기

1. 대상은 이 저장소 안의 파일뿐이다. `glob`으로 `**/CLAUDE.md`, `**/AGENTS.md`, `**/CLAUDE.local.md`, `**/AGENTS.local.md`를 찾는다. `node_modules`는 뺀다.
2. `git check-ignore -v CLAUDE.local.md AGENTS.local.md`로 두 개인 파일이 무시 대상인지 확인한다. 아니면 보고서의 문제 목록에 올린다.

## 3. 채점

파일마다 100점 만점으로 채점한다. 등급은 A 90 이상, B 70 이상, C 50 이상, D 30 이상, 그 아래는 F다.

| 항목             | 배점 | 만점 기준                                                                         |
| ---------------- | ---- | --------------------------------------------------------------------------------- |
| 명령과 작업 흐름 | 20   | 빌드, 테스트, lint 명령을 복사해서 바로 실행할 수 있다                            |
| 구조 설명        | 20   | 계층과 진입점을 읽고 코드 위치를 짐작할 수 있다                                   |
| 비자명한 규칙    | 15   | 코드만 봐서는 알 수 없는 함정과 관례가 있다                                       |
| 간결성           | 15   | 코드로 알 수 있는 내용과 일반론이 없다. 200줄을 넘지 않는다                       |
| 최신성           | 15   | 명령, 경로, 패키지가 지금 저장소와 맞는다                                         |
| 실행 가능성      | 15   | 지시가 태도가 아니라 동작으로 적혀 있다. 강제 장치가 있는 규칙은 그 장치를 적는다 |

최신성은 추정하지 않는다. 1단계 기계 검사 결과와 직접 실행한 명령으로 판정한다. 부작용이 있는 명령은 실행하지 않는다.

## 4. 보고

반영하기 전에 아래 형식으로 보고서를 낸다.

```text
## 지시 파일 품질 보고

### 요약
- 기계 검사: check:agents <결과>, check:claude-md <결과>
- 찾은 파일: N개, 평균 점수 NN/100

### 파일별 채점
#### 1. ./CLAUDE.md
점수: NN/100 (등급 X)
| 항목 | 점수 | 근거 |

### 변경 제안
| # | 위치 | 변경 | 이유 |

### 승격 후보 (CLAUDE.local.md → CLAUDE.md)
- 항목, 추가한 날짜, 충족한 조건과 충족하지 못한 조건
```

## 5. 변경 제안과 반영

1. 새 항목과 세션에서 배운 내용은 `CLAUDE.local.md`로 보낸다. 승격 조건을 모두 넘긴 항목만 `CLAUDE.md`로 보낸다. 낡은 명령과 경로는 그 파일에서 바로 고친다.
2. 반복해서 어기는 규칙은 문장을 강하게 고치지 않는다. lint 규칙, `.dependency-cruiser.mjs` 규칙, 검사 스크립트로 옮길 수 있는지 먼저 본다. 옮기면 지시 파일에는 규칙 한 줄과 그 규칙을 막는 검사 이름을 적는다.
3. 아래 표로 넣을 내용을 거른다.

| 넣는다                          | 넣지 않는다                      |
| ------------------------------- | -------------------------------- |
| 실제로 실행한 명령과 작업 순서  | 코드를 읽으면 알 수 있는 내용    |
| 코드에서 찾은 함정과 관례       | 일반 모범 사례                   |
| 패키지 사이의 관계              | 한 번 쓰고 끝난 수정             |
| `SPEC.md`에 없는 작업 방식 결정 | `SPEC.md`를 그대로 옮긴 요구사항 |

4. 변경마다 이유 한 줄과 diff를 보여 주고 사용자 승인을 받는다.
5. 승인받은 변경만 반영하고, 1단계 기계 검사를 다시 돌린다.
6. 승격한 항목은 `CLAUDE.local.md`에서 지운다. 바뀐 파일 목록과 승격을 기다리는 항목 수를 보고한다.

## 하지 않는 것

- 보고서 없이 파일을 고치지 않는다.
- 저장소 밖의 지시 파일(홈 디렉터리의 사용자 레벨 파일)을 찾거나 고치지 않는다.
- `SPEC.md`를 고치지 않는다. 바꿀 내용이 생기면 사용자에게 바뀌기 전과 후를 보여 준다.
